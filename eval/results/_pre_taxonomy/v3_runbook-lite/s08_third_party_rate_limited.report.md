# Incident Report: payments-api HTTP 429 Rate Limiting

## Summary
At 2026-08-30T03:12:00.000Z, `payments-api` began throwing 38% error rates due to HTTP 429 (Too Many Requests) responses from the external payment gateway (`PayGate`). Investigation revealed that a recent one-off refund backfill job (`worker-1.4.1`) running at concurrency 32 and sharing the production API key was exhausting the payment gateway rate limit quota (consuming 92% of calls), starving regular `payments-api` traffic.

## Timeline
- **02:46:00.000Z**: `worker-1.4.1` deployed with a one-off refund backfill job (18k refunds at concurrency 32), sharing the production API key.
- **03:10:00.000Z**: `payments-api` error rate spikes from ~0.4% to ~38%.
- **03:12:00.000Z**: P2 Alert fires (`charge_failed 38% (HTTP 429 from vendor)`).

## Root Cause
`third_party_rate_limited`: The payment gateway (`PayGate`) rate limit quota was exhausted by a high-concurrency background refund backfill job (`worker`) sharing the same API credentials as `payments-api`.

## Evidence
- `get_alert`: `payments-api` reporting 38% charge failures with HTTP 429 from vendor.
- `recent_changes`: `worker` deployed `worker-1.4.1` at 02:46 UTC with an 18k refund backfill job at concurrency 32, calling PayGate directly with the shared production API key.
- `run_probe`: HTTP probe to `api.paygate.example` confirmed the vendor is healthy (HTTP 200), but the vendor's rate-limit dashboard showed the API key at 100% of its 600/min quota, with 92% of calls generated by user-agent `worker/1.4.1`.
- `get_metrics`: `payments-api` `error_rate_pct` jumped from 0.4% to ~38-39% concurrently with the backfill job.

## Proposed Remediation
Enable a circuit breaker or rate limit control on the background worker's calls to PayGate (or pause the backfill job / separate its API credentials), and enable a circuit breaker in `payments-api` to gracefully shed or queue refund backfill traffic while protecting core checkout traffic. The safest immediate containment action is to enable a circuit breaker / rate limiter targeting the background worker or pause the backfill job.
